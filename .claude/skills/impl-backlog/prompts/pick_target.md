先に `git fetch origin main` を実行する。

対象を決める。
- ユーザー指定の ID / タイトルがあればそれ。
- 指定が無ければ `task backlog:next REF=origin/main` を実行し、ready 欄の先頭（最も優先度が高く ID が最小）を、**了承を取らずに**選ぶ。
- ready 欄が空なら、todo 欄の先頭を提案して、ユーザーの了承を得る（ユーザーに聞くのはここだけ）。
- `# Done` 節の項目は対象外。

次を確かめる。
- **依存先は `origin/main` で確かめる**: 手元の `BACKLOG.md` は、未マージのブランチ上だと依存先が完了に見える。指定された項目が `task backlog:next REF=origin/main` の blocked 欄にあれば、着手せずに待っている依存先を伝え、先に依存先を実装することを提案して止まる。
- 依存先が手元のブランチにだけ完了とある（`origin/main` に無い）場合は、着手せず、そのブランチの PR が未マージであることを伝える。「マージを待つ」「そのブランチを起点に積む」「別の項目にする」の中から、ユーザーに選んでもらう。「そのブランチを起点に積む」「別の項目にする」が選ばれたら、その決定に従って対象を決め直す。「マージを待つ」なら止まる。
- `git status` で、`BACKLOG.md` に対象以外の項目の未 commit の変更があれば、着手せずに伝えて止まる（この項目の PR に混ざるため）。
