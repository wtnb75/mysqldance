`gh pr create --base main --title "B-NNN: <項目のタイトル>"` で PR を作る。次の場合は `--draft` を付ける（項目は完了にしない）。未達の条件と理由を本文に書く。
- 満たせなかった受け入れ条件がある
- 必須の統合テストを実行できなかった（Docker が使えないなど）

本文は日本語で、次の順に書く。
- 概要（項目の内容と、何を変えたか）
- 確定した仕様と、置いた前提（項目の `- 仕様:` と、後半で置いた前提）
- 受け入れ条件の結果（1つずつ）
- チェックの結果（実行したタスクと結果。統合テストを実行したか）
- レビューの判断（指摘 / 判断 / 理由の表。台帳で却下したものは台帳の ID）
- 別項目にしたもの（ID）
- 確認していないこと
